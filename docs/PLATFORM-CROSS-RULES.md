# 웹·앱 동시 개발 필수 규칙 (NullReference Music)

이 문서는 이 저장소에서 AI·개발자가 **반드시** 지켜야 하는 플랫폼 전제입니다. 요청에 명시되지 않아도 적용합니다.

## 1. 동시 고려

- 모든 기능 추가·수정·리팩터는 **웹(`Platform.OS === 'web'`)과 네이티브(iOS/Android)** 를 **동시에** 고려합니다.
- 한 플랫폼만 고친다고 해서 다른 플랫폼이 깨지면 안 됩니다.

## 2. 상호 비간섭

- **웹에서 고친 것이 앱을 깨뜨리면 안 되고, 앱에서 고친 것이 웹을 깨뜨리면 안 됩니다.** 한 플랫폼용 수정이 다른 플랫폼 번들·런타임에 섞이지 않게 합니다.
- **웹 번들**과 **앱(Expo Go / 개발 빌드 / 배포 APK·IPA)** 은 서로 **코드·번들 의존성을 공유하되**, 플랫폼에 맞지 않는 네이티브 전용 패키지나 브라우저 전용 API가 **상대방 빌드를 깨지 않게** 분리합니다.
- Hermes 전용 **DOM 폴리필**(`EventTarget` 등)은 **`nrmDomMinimalPolyfills.native.ts` + `nrmDomMinimalPolyfills.web.ts`** 처럼 **파일 단위로만** 넣고, 웹·앱이 동일한 `import` 경로를 쓰되 Metro가 **서로 다른 파일**을 묶게 합니다. **한 파일 안에서 `Platform.OS`로 감싼 `import 'some-polyfill-package'`** 는 번들러가 **웹에서도 그 모듈을 해석**하므로 지양합니다.
- 예: `youtubei.js`처럼 웹 Metro에서 문제되는 의존성은 **`*.web.ts` / `*.native.ts`** 분리 또는 진입 모듈에서 **플랫폼별 동적 import**로 격리합니다.

## 3. 앱 동작 동등성

- **Expo Go**와 **스토어용 APK/IPA**는 바이너리가 다르므로 100% 동일할 수는 없지만, **비즈니스 로직·네트워크** 관점에서는 다음을 목표로 합니다.
  - NullReference **백엔드(PC)** 에 의존하지 않는 플로우(검색·기기 저장 등)는 **Expo Go = 릴리스 빌드**와 같은 코드 경로를 씁니다.
  - PC 개발 서버 URL 자동 추론 등 **개발 전용** 편의는 웹 또는 명시적 설정에만 두고, 네이티브 기본 동작을 오염시키지 않습니다.

## 4. 검증 습관

- 웹 관련 수정 후: `npx expo export --platform web`(또는 `expo start --web`)으로 **웹 번들 성공**을 확인합니다.
- 네이티브 관련 수정 후: 가능하면 **iOS/Android** 각각 또는 최소 한 플랫폼에서 실행해 확인합니다.

## 5. 문서 위치

- 플랫폼 분리 패턴을 바꿀 때는 이 파일과 실제 코드(`lib/nrmInnertubeYoutube*.ts`, `apiBaseUrl.ts` 등)를 함께 갱신합니다.
